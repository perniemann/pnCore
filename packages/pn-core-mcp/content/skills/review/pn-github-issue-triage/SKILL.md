# GitHub issue triage

## When to use

- Maintainer (or delegate) wants to **triage**, label, or groom Issues for AFK agents or humans.
- User invokes natural-language requests such as “what needs attention”, “move #42 to ready-for-agent”, “prepare agent brief for #17.”

## Prerequisites

- **[GitHub MCP server](https://github.com/github/github-mcp-server)** with **`issues`**, **`labels`**, and **`context`** toolsets minimum (`repos` if discovery helpers required). See [server configuration](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md).
- **`gh`** or browser auth is **not** required when MCP is configured.

If GitHub MCP is unavailable: say so and offer to draft triage notes in-repo only — **do not** claim GitHub was updated.

## Label taxonomy (editable defaults)

**Replace these names** with your organization’s labels. Every Issue should have **one category** and **one state** label when your policy requires both.

| Label | Role | Meaning |
|-------|------|---------|
| `bug` | Category | Something is broken |
| `enhancement` | Category | Feature or improvement |
| `needs-triage` | State | Maintainer must evaluate |
| `needs-info` | State | Waiting on reporter |
| `ready-for-agent` | State | Specified enough for AFK agent |
| `ready-for-human` | State | Needs human implementation |
| `wontfix` | State | Will not be actioned |

If two **state** labels conflict on one Issue, **flag the conflict** and recommend resolution before applying changes.

## State transitions (editable defaults)

| From | Can move to | Notes |
|------|-------------|--------|
| Unlabeled | `needs-triage`, `ready-for-agent`, `ready-for-human`, `wontfix` | First touch |
| `needs-triage` | `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` | After evaluation |
| `needs-info` | `needs-triage` | Reporter replied — surface for re-review |

Overrides are allowed if policy says so; flag **unusual** transitions.

## AI disclaimer (comments)

When posting triage comments to GitHub, include at the **top** of the comment body **if policy allows**:

```markdown
> *This was generated by AI during triage.*
```

If the project forbids disclaimer boilerplate, **omit** this block.

## Optional: out-of-scope knowledge

If the repo uses `.out-of-scope/*.md` for rejected ideas, **read** before recommending `wontfix` / enhancement rejection — cite similar prior rejections when relevant.

## Workflows

### Show what needs attention

Query Issues (open) grouped conceptually:

1. **Unlabeled** — never triaged.
2. **`needs-triage`** — awaiting maintainer.
3. **`needs-info`** with **new reporter activity** since last triage comment (compare comment timestamps).

Show counts; within each bucket, **oldest first**. One-line summary per Issue.

### Triage one Issue

1. Read body, labels, comments, reporter metadata.
2. Explore codebase **lightly** for domain context (no deep fix unless asked).
3. Present **Category** recommendation (`bug` vs `enhancement`) and **State** recommendation with reasoning.
4. On approval: apply labels via GitHub MCP **`labels`** capabilities; post triage summary comment with optional disclaimer.
5. If **ready-for-agent**: add a short **agent brief** in the comment (goal, acceptance shape, constraints) — durable language, minimal file-path coupling.
